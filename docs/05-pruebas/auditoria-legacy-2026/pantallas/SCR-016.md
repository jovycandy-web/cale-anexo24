## B. Propósito funcional

Catálogo de **actividades/autorizaciones** del sistema. Cada actividad es una clave (`CACT*`, `CUSR*`, `MODENT*`, etc.) que habilita el acceso a una pantalla o una operación específica (consultar, generar, exportar, agregar, editar, eliminar). Es el bloque base del modelo RBAC del sistema y la explicación probable de por qué ciertas acciones aparecen ocultas para el perfil.

## P. Especificación para aplicación sustituta

1. **Modelo RBAC:** catálogo de actividades (clave, nombre) + asignación a perfiles + usuario con perfil.
2. **Convención:** `<MODULO><n>` para operaciones; el acceso a pantalla es una actividad propia (`ACCESO A ...`).
3. **UI:** catálogo con alta/edición/borrado y exportación; validar unicidad de clave.
4. **Menú dinámico:** mostrar secciones sólo si el perfil tiene las actividades correspondientes (evitar secciones vacías como H-001).
5. **Migración:** mapear las 52 actividades a permisos del nuevo sistema; las pantallas ocultas (UPLARCH, REPMOV) deben decidirse explícitamente (implementar o descartar).
